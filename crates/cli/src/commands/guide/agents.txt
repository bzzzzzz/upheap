For agents

Naming
- An item is named by its key (k3x9a), by team/heap/key, or by a link to it. A key names the same item for good;
  a position in the list doesn't, so never keep one.
- A step is its item's key and its number: k3x9a.3. A question is k3x9a.q2, a comment k3x9a.c3.
- A heap is team/heap. A command marked [heap] works in the heap --heap names, or else UPHEAP_HEAP, or else the
  default set with `upheap heap use`. With none of them it fails and says how to set one.
  `upheap item list --all-heaps` lists every heap's items in one ranked list, each with its heap, and needs no heap
  set.

Output
- Results go to stdout, errors to stderr. Without a flag the output is text for people.
- --json prints the server's response body unchanged, and a refusal's problem body on stderr.
- -q prints only what the next command needs: `upheap item add -q` the new item's key, `upheap step add -q` the
  step (k3x9a.3), `upheap question ask -q` the question (k3x9a.q1), `upheap comment add -q` the comment (k3x9a.c3),
  `upheap item list -q` the keys in ranked order (with --all-heaps, team/heap/key).

Exit codes
  0  done, or nothing to do
  1  unexpected: a bug in the tool or the server
  2  the command line was wrong; nothing was sent
  3  the server refused the request, or a name on the command line matched nothing
  4  not signed in, not allowed, or not found
  5  the server couldn't be reached
  6  the setup on this machine is broken: the config file or the keychain
- On 4 with a message about signing in, stop and tell the person: `upheap auth login` needs their browser.
- On 3 with a conflict, someone changed the item since you read it: read it again before writing.

Long text
- Anything longer than a line goes in from a file: write the file, then pass it with --context-file (an item's,
  a step's or a heap's context), --details-file (a question's long version), --comment-file (a reply's comment) or
  --file (a comment). `-` in place of the file reads stdin.
- `upheap item add` takes the context with --context-file too, and a task's steps with --step, so a task with its
  context and steps is one call. If a step fails, the item stays added with the steps before it, and the output
  names its key: add the rest with `upheap step add`, don't add the item again.

The usual order of work
1. `upheap heap show`: the heap's context says what the project is and how work is done in it. Read it first.
2. `upheap item list`: the ranked list, the most worth doing first. `upheap item show` prints one item in full,
   with its context, comments, steps, and questions with their answers.
   A reminder, added with `upheap item add "<title>" --reminder <date>`, stays out of the list until that date;
   `upheap item list --reminders shown` lists those still to come.
3. Write what you learn, decide or do where the next reader will look: as a comment on the item, with
   `upheap comment add`, not in your reply. A comment adds to the item without touching its context. Rewrite the
   context, with --context-file on `upheap item edit`, only when what the item is has changed: it had none, or
   the task or what done looks like turned out different from what is written. Progress, findings and decisions
   are never a reason to rewrite it.
   Work with parts is a task: `upheap item add --task`, or `upheap item to-task` for a note that turns out to be one,
   then a step for each part, ticked as each one is finished.
   Mark how far it's prepared with --stage on `upheap item edit`: with_context once it has its context and no
   open question, defined once a task also has its steps. In a run, `upheap work reached` moves the stage instead,
   and `upheap work hand-back --reason "<why>"` gives the turn back when there is nothing to do.
   `upheap parameter list` shows the heap's parameters and their options; give an item one with
   `--parameter NAME=OPTION` on `upheap item add` or `upheap item edit`. An admin sets a heap's parameters up with
   `upheap parameter add` and `upheap parameter edit`, and their options with `upheap parameter option add`, `edit`
   and `archive`.
4. When a call is the person's to make, don't guess: ask with `upheap question ask`, with --choice for each answer
   when you can list them, or with `upheap question request` for something only they can do. The item then waits
   for them, and their answer reads back in `upheap item show`. When they answer in the conversation, record it
   with `upheap question reply k3x9a.q1 --pick Internal` or `--comment "..."`. Their sign-in is what replies, so
   reply only with what they said.

Example
  upheap item add "Rotate the staging certs" --effort s --task --context-file context.md --step "Order the new certificate" --step "Install it in staging" -q    # prints the key, say k3x9a
  upheap question ask k3x9a "Which CA do we use?" --choice "Internal" --choice "Let's Encrypt"
  upheap comment add k3x9a "Staging uses the internal CA; production still has the old certificate."
  upheap item start k3x9a
  upheap step tick k3x9a.1
  upheap item done k3x9a
