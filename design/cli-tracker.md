## Steps

| Step | What | Status | Notes |
| --- | --- | :---: | --- |
| 1 | Server: OAuth with PKCE, bearer tokens, the consent page | ✅ | `GET/POST /oauth/authorize` for the consent page, `POST /oauth/token` and `POST /oauth/revoke` for the client (form-encoded, RFC error format, no CSRF header). One client, `upheap-cli`, with `http://127.0.0.1` and `http://[::1]` redirect URIs on any port. Codes last 10 minutes and work once; access tokens 15 minutes; refresh tokens 30 days, rotated on every use, and a reused one revokes its family; revoking is one row of `oauth_token_families`, which a refresh locks. `Authorization: Bearer` resolves to the same `Principal` as a session cookie and needs no CSRF header. The web app's `/oauth/authorize` page signs in first when needed, then asks Allow or Cancel, with Use another account. The web app can't be framed (`X-Frame-Options`, CSP `frame-ancestors`). Tables `oauth_auth_codes`, `oauth_token_families` and `oauth_tokens` |
| 2 | `crates/api-types`: move the DTOs out of `api` | ✅ | No behaviour change: `openapi.json` is byte-identical. Done in the same pull request as step 3, as its own commit. `api-types` has no IO and depends on nothing in the workspace but `domain`; it keeps the conversions between DTOs and domain types; conversions from service views (`ItemView`, `RankedEntry`, `TeamDetail`…) and those that need the request stay in `api` as plain functions (`to_item_dto`, `to_team_dto`), since the orphan rule forbids `From` impls there. Response types also derive `Deserialize`; the list, closed-list and OAuth request types derive `Serialize`. `Problem` and the OAuth bodies hold `String`s, not `&'static str`. Path and header parameter docs (`HeapParams`, `IfMatchHeader`, `TimeZoneHeader`) stay in `api`, with the extractors that read them |
| 3 | `crates/cli`: config, HTTP client, `upheap auth login` / `auth logout`, `upheap heap list` / `heap use`, `upheap item list` | ✅ | Login opens the browser on `/oauth/authorize` (and prints the address), listens on `127.0.0.1:<free port>/callback` with a task per connection (preconnects send nothing), turns away a redirect with another `state` and keeps waiting, and gives up after 5 minutes; Cancel is `error=access_denied`, exit 4. Logout calls `/oauth/revoke` and succeeds when not signed in; `--local` forgets a sign-in whose server is gone. Login replaces an earlier sign-in under the token lock. Plain `http` only to this machine, and no redirects followed. Human output shows control characters in server text as U+FFFD. An unreadable keychain entry is overwritten by login and forgotten by `logout --local`. A default heap stays paired with its server; config writes re-read the file and replace it atomically. A cut-off response and a proxy's `502`/`504` are exit 5. No proxy for a server on this machine. Any failure after login's code exchange, or a refresh the keychain won't keep, revokes the new tokens. `--json` on a terminal escapes DEL and C1. Config writes hold `config.lock`. Unknown `allowed_actions`, factors and closed groups from a later server are skipped or read as `Unknown` (cli.md, Code layout). The sign-in (refresh token, access token and its expiry) is one keychain entry per server (`keyring` 4: macOS keychain, Windows, Secret Service over pure-Rust zbus, so no libdbus); no keychain is exit 6. A fresh access token is reused; a refresh happens under an exclusive lock on `tokens.lock` in the config directory, after reading the tokens again, so two `upheap`s never spend one refresh token twice; a refused refresh forgets the sign-in, exit 4. Config is plain `toml` + serde, not `confique`, as the CLI writes it too. A lib with a thin bin: `cli::run(args, Deps)`; the tests run the real router on a localhost port and drive login through the real consent endpoints. Behind a Basic-auth proxy the CLI needs `/api` let through (technical-design.md) |
